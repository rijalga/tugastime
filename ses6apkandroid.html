01

Prinsip Dasar Layout & View

Analogi Komponen: Bayangkan `View` sebagai barang-barang di dalam kamar (meja, kursi, lampu), sedangkan `ViewGroup` adalah dinding dan tata ruang kamar itu sendiri yang mengatur di mana barang-barang tersebut diletakkan.

Dalam Android, antarmuka pengguna dibangun menggunakan hierarki objek `View` dan `ViewGroup`. Setiap komponen visual yang terlihat pada layar aplikasi chat adalah turunan dari `View`.

Elemen UI

View

Elemen UI tunggal yang menggambar sesuatu di layar dan merespons interaksi pengguna. Contoh: `TextView`, `Button`, `ImageView`.

Wadah Layout

ViewGroup

Wadah tak kasat mata yang menampung `View` lain dan menentukan aturan posisinya. Contoh: `LinearLayout`, `ConstraintLayout`.

Perbandingan 3 Layout Utama

Tipe Layout Mekanisme Posisi Kelebihan / Kasus Penggunaan
LinearLayout Menyusun elemen secara sejajar (Vertikal / Horizontal). Sederhana, cocok untuk form baris atau daftar linier dasar.
ConstraintLayout Menentukan posisi relatif terhadap elemen lain atau parent. Fleksibel, meratakan hierarki layout kompleks agar performa cepat.
FrameLayout Menumpuk elemen di atas elemen lain (z-axis). Ideal untuk kontainer fragment atau overlay loading/badge.
Mockup Visual Hierarki Layout Chat
[ConstraintLayout Parent]
├── Header Bar (LinearLayout Horizontal)
├── Chat List (RecyclerView)
└── Input Panel (LinearLayout Horizontal)

Kesalahan Umum

Sarang layout (`nested LinearLayout`) terlalu dalam yang menurunkan performa render frame UI.

Perbaikan

Gunakan `ConstraintLayout` sebagai root layout utama untuk mendatarkan (*flatten*) hierarki XML.

Latihan Mandiri

Ubah layout berundak 3 tingkat menjadi 1 tingkat `ConstraintLayout` pada komponen item chat.

Instruksi Penting: Selalu utamakan ConstraintLayout untuk tampilan layar utama agar proses pemrosesan posisi (layout pass) berjalan efisien.

02

Anatomi Layar Aplikasi Chat

Analogi Struktur Layar: Layar chat seperti papan pengumuman interaktif. Header sebagai judul papan, RecyclerView sebagai deretan papan surat bergulir, dan Input Bar sebagai kotak penulisan di bagian bawah.

Layar utama antarmuka chat Firebase terdiri dari tiga bagian vital: Header Informasi lawan bicara, Area Pesan bergulir (RecyclerView), dan Baris Pengiriman pesan.

[Header] Status Lawan Chat
Pesan Masuk (Received)
Pesan Keluar (Sent)

Struktur XML `activity_main.xml`

<androidx.constraintlayout.widget.ConstraintLayout 
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <include
        id="@+id/layoutHeader"
        layout="@layout/layout_chat_header"
        app:layout_constraintTop_toTopOf="parent" />

    <androidx.recyclerview.widget.RecyclerView
        android:id="@+id/rvMessages"
        android:layout_width="0dp"
        android:layout_height="0dp"
        app:layout_constraintTop_toBottomOf="@id/layoutHeader"
        app:layout_bottom_toTopOf="@id/layoutInputBar"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent" />

    <include
        id="@+id/layoutInputBar"
        layout="@layout/layout_chat_input"
        app:layout_constraintBottom_toBottomOf="parent" />

</androidx.constraintlayout.widget.ConstraintLayout>

Kesalahan Umum

Menggunakan `ScrollView` menampung `RecyclerView`, menyebabkan pemborosan memori dan scroll macet.

Perbaikan

Biarkan `RecyclerView` menangani guliran secara mandiri dengan tinggi `0dp` (`match_constraint`).

Latihan Mandiri

Tambahkan atribut `app:stackFromEnd="true"` pada RecyclerView agar pesan otomatis bergulir ke bawah.

Instruksi Penting: Gunakan tag <include> untuk memecah berkas XML yang panjang menjadi modul-modul kecil agar lebih mudah dipelihara.
Dosen: Muhammad Rijal, S.Kom., M.Kom. | Institut Teknologi dan Bisnis Nobel Indonesia
03

Widget View & Controller

Analogi Controller: Jika `View` adalah instrumen musik, maka `Activity` & `Adapter` adalah konduktor musiknya yang mengatur kapan instrumen harus berbunyi berdasarkan data dari backend Firebase.

Integrasi antara elemen visual XML dan logika Kotlin dikendalikan oleh Controller melalui mekanisme ViewBinding dan Adapter.

Tabel Widget Utama Aplikasi Chat

Komponen Widget Tipe View Fungsi Utama dalam Chat
`tvMessageBody` TextView Menampilkan teks isi pesan chat.
`etInputMessage` EditText Menerima ketikan masukan pesan dari pengguna.
`btnSend` ImageButton / Button Memicu fungsi pengiriman data ke Firebase.
`ivUserProfile` ImageView Menampilkan foto profil pengguna/lawan bicara.
`rvMessages` RecyclerView Menampilkan daftar riwayat pesan secara efisien.

Activity / Fragment

Bertindak sebagai Controller utama pengendali siklus hidup (*lifecycle*) layar, inisialisasi peristiwa klik, serta mendengarkan perubahan data Firebase Realtime Database.

RecyclerView.Adapter

Jembatan penghubung antara koleksi data list (`List`) dan ViewHolder. Mengatur daur ulang View agar penggunaan memori efisien.

ViewBinding

Fitur pengganti `findViewById` yang aman tipe (*type-safe*) dan aman null (*null-safe*) untuk mengakses elemen widget dari XML secara langsung.

Kesalahan Umum

Memanggil `findViewById` berulang kali di dalam metode `onBindViewHolder` pada Adapter.

Perbaikan

Gunakan pola `ViewHolder` bersama `ViewBinding` untuk menyimpan referensi widget.

Latihan Mandiri

Aktifkan `viewBinding { enable = true }` pada berkas `build.gradle.kts` modul aplikasi Anda.

Instruksi Penting: Selalu bersihkan referensi Binding pada Fragment saat onDestroyView untuk mencegah kebocoran memori (memory leak).

Resource Aplikasi Android

Analogi Resource: Resource adalah kamus aset terpusat. Mengubah nilai di berkas XML Resource seperti mengubah konstanta di satu tempat; seluruh tampilan aplikasi akan otomatis terbarui tanpa perlu mengubah kode logika.

Penyimpanan aset terpisah di folder `res/` memfasilitasi lokalisasi, pemeliharaan warna, serta konsistensi ukuran jarak antarmuka.

Palet Warna Terbatas (Maksimal 5 Warna)

Primary (Terra)
#C06B4E
Secondary (Sage)
#8A9A5B
Accent (Sand)
#D9C3A5
Background (Cream)
#F5EFE6
Text/Dark (Brown)
#3E2C23

Contoh Berkas Resource Utama

res/values/colors.xml 
<resources>
    <color name="brand_primary">#C06B4E</color>
    <color name="brand_secondary">#8A9A5B</color>
    <color name="surface_sand">#D9C3A5</color>
    <color name="bg_cream">#F5EFE6</color>
    <color name="text_brown">#3E2C23</color>
</resources>
res/values/strings.xml 
<resources>
    <string name="app_name">ChatNobel</string>
    <string name="hint_type_message">Ketik pesan...</string>
    <string name="action_send">Kirim</string>
</resources>
res/values/dimens.xml 
<resources>
    <dimen name="spacing_small">8dp</dimen>
    <dimen name="spacing_medium">16dp</dimen>
    <dimen name="text_size_body">14sp</dimen>
</resources>

Kesalahan Umum

Menuliskan nilai warna Hex atau teks biasa secara langsung (*hardcoded*) di XML layout.

Perbaikan

Gunakan `@color/` dan `@string/` agar aplikasi mendukung tema serta multi-bahasa.

Latihan Mandiri

Ekstrak seluruh teks pada `activity_main.xml` ke dalam `strings.xml` menggunakan pintasan `Alt+Enter`.

Instruksi Penting: Gunakan satuan 'dp' untuk ukuran tata letak/padding dan 'sp' khusus untuk ukuran font teks.

05

Style & Theme Android

Analogi Style vs Theme: `Style` adalah seragam khusus untuk satu elemen (misal: gaya gelembung chat pesan terkirim), sedangkan `Theme` adalah aturan busana keseluruhan aplikasi yang berlaku secara global.

Style meminimalkan duplikasi kode XML layout, sementara Theme mengatur atribut konsistensi warna aplikasi pada tingkat global.

Definisi Style Gelembung Chat (`styles.xml`)

<resources>
    <!-- Base Style Gelembung Chat -->
    <style name="ChatBubble">
        <item name="android:padding">@dimen/spacing_small</item>
        <item name="android:textColor">@color/text_brown</item>
        <item name="android:textSize">@dimen/text_size_body</item>
    </style>

    <!-- Gelembung Pesan Terkirim -->
    <style name="ChatBubble.Sent">
        <item name="android:background">@color/brand_secondary</item>
        <item name="android:textColor">#FFFFFF</item>
    </style>

    <!-- Gelembung Pesan Diterima -->
    <style name="ChatBubble.Received">
        <item name="android:background">@color/surface_sand</item>
    </style>
</resources>

Tema Global Aplikasi (`themes.xml`)

<resources xmlns:tools="http://schemas.android.com/tools">
    <style name="Theme.ChatApp" parent="Theme.MaterialComponents.DayNight.NoActionBar">
        <item name="colorPrimary">@color/brand_primary</item>
        <item name="colorSecondary">@color/brand_secondary</item>
        <item name="android:statusBarColor">@color/text_brown</item>
        <item name="android:windowBackground">@color/bg_cream</item>
    </style>
</resources>

Tabel Pengujian Kontras Warna (Standar WCAG)

Elemen UI Warna Background Warna Teks Rasio Kontras Status Aksesibilitas
Pesan Terkirim Sage (`#8A9A5B`) White (`#FFFFFF`) 4.5:1 Lulus AA
Pesan Diterima Sand (`#D9C3A5`) Brown (`#3E2C23`) 7.2:1 Lulus AAA
Header App Primary (`#C06B4E`) White (`#FFFFFF`) 4.6:1 Lulus AA

Kesalahan Umum

Mengulang deklarasi `textSize`, `padding`, dan `fontFamily` di setiap tag `TextView` XML.

Perbaikan

Ekstrak properti yang berulang ke dalam satu induk `style` terpusat.

Latihan Mandiri

Buat turunan style `ChatBubble.System` untuk pesan info status (misal: "Pesan telah dibaca").

Instruksi Penting: Pastikan rasio kontras teks terhadap warna latar minimal 4.5:1 untuk memenuhi standar aksesibilitas WCAG.

06

Praktik Kelompok

Analogi Tim Pengembang: Pembuatan aplikasi mobile di industri membagi peran secara spesifik. Kolaborasi 4 anggota meniru alur kerja nyata tim software engineering.

Setiap kelompok terdiri dari 4 mahasiswa yang berkolaborasi mengonversi rancangan layout ke dalam proyek aplikasi chat Firebase.

Pembagian Peran Kelompok (4 Anggota)

Peran Tanggung Jawab Utama Output Deliverable
UI Designer (A1) Merancang layout XML, memecah komponen, dan mengelola Resource `colors.xml` & `dimens.xml`. `activity_main.xml`, `item_chat.xml`
Style Master (A2) Menyusun `styles.xml`, `themes.xml`, dan memastikan aksesibilitas kontras warna antarmuka. `styles.xml`, `themes.xml`
Adapter Engineer (A3) Membuat `RecyclerView.Adapter` dan mengimplementasikan ViewBinding pada ViewHolder. `MessageAdapter.kt`
Firebase Controller (A4) Mengisi data dari Realtime Database ke Adapter serta menangani aksi klik kirim pesan. `MainActivity.kt`

Langkah Kerja & Estimasi Waktu (Total 100 Menit)

  1. Tahap 1 (15 Menit): Pembagian tugas dan penyelarasan variabel Resource 5 warna.
  2. Tahap 2 (30 Menit): Konstruksi layout XML (`ConstraintLayout` & `RecyclerView`).
  3. Tahap 3 (30 Menit): Pembuatan Style, Theme, serta pengodean `MessageAdapter.kt`.
  4. Tahap 4 (25 Menit): Pengujian integrasi pengiriman pesan Firebase & evaluasi peer review.

Kesalahan Umum

Mengerjakan kode pada modul bertumpukan tanpa pembagian pembagian berkas yang jelas.

Perbaikan

Gunakan arsitektur komponen terpisah (Layout XML, Style Resource, Adapter, Activity).

Latihan Mandiri

Lakukan *merge* kode antar anggota tim menggunakan Git branching per peran.

Instruksi Penting: Pastikan seluruh anggota kelompok melakukan pengujian tampilan pada emulator dengan resolusi layar berbeda.

Gunakan checklist 10 poin interaktif di bawah ini untuk menguji kelengkapan modul praktikum Anda secara mandiri.

Skor Kelengkapan: 0 / 10

Rubrik Peer Review Kelompok (Skala 1 - 4)

Kriteria Penilaian Skor (1 - 4)
